# گزارش فاز ۸ — بررسی فنی و امنیتی پیش از انتشار

تاریخ جمع‌بندی: ۱۵ اکتبر ۲۰۲۶. مبنا نسخهٔ تحویلی فاز ۷ است. این مرحله روی کد و خروجی محلی انجام شده؛ هیچ انتشار، تغییر DNS، ورود واقعی پنل یا ارسال ایمیل واقعی انجام نشده است.

**نتیجه: نسخه برای انتشار آزمایشی آماده است. تأیید انتشار عمومی نهایی به اصلاح متن حریم خصوصی و آزمایش اتصال‌های واقعی وابسته است.** این گزارش ادعای نبود همهٔ باگ‌ها یا ممیزی نفوذ مستقل ندارد.

## اصلاحات

- HTML مقاله‌ها در زمان ساخت با فهرست مجاز پردازش می‌شود؛ اسکریپت، رویدادهای HTML، آدرس خطرناک، فرم و embed پذیرفته نمی‌شوند. خروجی پاک‌سازی‌شده در صفحه، خوانندهٔ سریع و RSS استفاده می‌شود. ۱۲ بدنهٔ فعلی مقاله‌ها بدون تغییر باقی مانده‌اند.
- فایل رسانه با محتوای واقعی، اندازه و مسیر بررسی می‌شود: تصویر حداکثر ۴۰ میلیون پیکسل و فایل حداکثر ۲۰ MiB؛ خروج از پوشهٔ عمومی با مسیر یا پیوند نمادین رد می‌شود. PDF از روی امضای فایل بررسی می‌شود؛ این بررسی اسکن بدافزار یا حذف قابلیت‌های فعال PDF نیست.
- CSP برای اسکریپت‌ها از hash استفاده می‌کند و `unsafe-inline` یا `unsafe-eval` ندارد. رویدادهای درون HTML ممنوع‌اند. سبک‌های درون HTML برای حفظ طراحی همچنان مجازند. منابع تصاویر HTTPS مجازند؛ سیاست به‌معنی قطع همهٔ ارتباطات بیرونی نیست.
- هر خروجی فایل `_headers` برای CSP، جلوگیری از تشخیص اشتباه نوع فایل، محدودیت قاب، سیاست ارجاع و مجوزهای مرورگر دارد. CSP متا نیز در همهٔ HTMLهاست. اجرای کامل هدرها وابسته به میزبان است؛ متا جای هدر HTTP را نمی‌گیرد.
- فرم تماس محدودیت طول، جلوگیری از ارسال تکراری، مهلت درخواست و فیلد تلهٔ ربات دارد. این‌ها کنترل سمت مرورگرند و جلوی درخواست مستقیم به EmailJS را تضمین نمی‌کنند؛ محدودیت دامنه در حساب سرویس باید فعال شود.
- پاسخ سرویس فعالیت GitHub اعتبارسنجی می‌شود. در حالت کاهش حرکت، مکث لودر حذف شده؛ حالت عادی حفظ شده است.
- GitHub Actions به شناسهٔ کامل commit مقید شده، دسترسی مخزن فقط خواندنی است و اعتبارنامهٔ checkout باقی نمی‌ماند. بررسی وابستگی و آزمون امنیتی در گردش کار قرار دارند. Dependabot تنظیم شده؛ اجرای واقعی آن نیازمند قراردادن فایل‌ها در مخزن است.
- ساخت نهایی بررسی امنیت خروجی را نیز اجرا می‌کند. در بررسی میانی یک خروجی فارسی متای CSP نداشت؛ خروجی بازسازی شد و کنترل ذخیرهٔ هر صفحه و کنترل نهایی ساخت اضافه شد. علت آن ناهماهنگی میانی با قطعیت مشخص نشد؛ نتیجهٔ تحویلی دوباره بررسی شده است.

| آزمون امنیتی Node | ۴ موفق: HTML اصلی، ورودی‌های مخرب، قالب مجاز و رسانه |

| سئو | ۴۸ صفحهٔ قابل نمایه‌سازی، canonical، hreflang، فارسی، sitemap و دادهٔ ساخت‌یافته |
| مقاله و RSS | ۱۲ صفحه و ۳ خوراک |
| خروجی انتشار | ۵۴ صفحه و ۱۴۲۲ ارجاع محلی؛ CSP و فایل‌ها تأیید شدند |

شواهد در `phase8/`، `browser-test-results.json` و `content-comparison.json` قرار دارند. آزمون مرورگر شامل سه زبان، دو تم، عرض موبایل، دسترس‌پذیری سناریوهای موجود، ۴۰۴، پنل ورودی، فرم با پاسخ ساختگی و مسدودشدن اسکریپت و ارتباط غیرمجاز است. این مجموعه جای آزمون تمام نسخه‌های Safari/Firefox یا گوشی فیزیکی را نمی‌گیرد. نتیجهٔ صفر آسیب‌پذیری فقط دربارهٔ موارد شناخته‌شده در پایگاه وابستگی در زمان اجراست.

بررسی الگوهای کلید خصوصی و توکن‌های متداول انجام شده؛ اسکن جامع همهٔ انواع راز یا بازبینی تاریخچهٔ مخزن انجام نشده است. شناسه‌های عمومی مرورگر EmailJS راز نیستند. داده‌های محتوایی اصلی و ترجمه‌ها با فاز ۷ مقایسه می‌شوند و نتیجه در `phase8/source-preservation.json` است.

## موارد باقی‌مانده برای انتشار عمومی

۱. متن حریم خصوصی قدیمی می‌گوید اطلاعات به طرف ثالث داده نمی‌شود؛ این جمله با EmailJS و ارائه‌دهندهٔ ایمیل سازگار نیست. پیش‌نویس سه‌زبانه در `privacy-proposed-en-de-fa.md` آماده است و هنوز داخل سایت اعمال نشده. سیاست نگهداری پیام‌ها نیز باید توسط صاحب سایت تعیین شود.

۲. ورود و ذخیرهٔ واقعی Pages CMS، سبزشدن Actions در حساب صاحب مخزن و انتشار نتیجه باید آزمایش شوند. `/admin/` یک راه ورود عمومی است، نه محل نگهداری رمز یا پنل مستقل.

۳. هدرها و HTTPS روی میزبان واقعی، سه دامنه، مسیرهای مستقیم و ۴۰۴ واقعی باید بررسی شوند. GitHub Pages فایل `_headers` را اعمال نمی‌کند. اگر همین میزبان حفظ شود، برای هدرهای کامل به تنظیمات لایهٔ میزبان یا پراکسی سازگار نیاز است. راهنمای `release-steps-fa.md` مسیر جایگزین و دستور بررسی را توضیح می‌دهد.

۴. EmailJS باید فقط مبدأهای مجاز را بپذیرد؛ قالب و صندوق مقصد باید با یک پیام واقعی از سایت منتشرشده آزموده شوند. صندوق عمومی `cian@kiankhayat.me` جداگانه باید موجود یا فوروارد شده باشد.

۵. هشت مدرک فعلی فایل واقعی ندارند؛ برای فعال‌شدن دریافت، تصاویر یا PDF واقعی باید توسط صاحب سایت افزوده شوند. این وضعیت نقص ساخت یا دانلود جعلی نیست.

مشاهدهٔ سایت قبلی: دامنهٔ اصلی پاسخ ۲۰۰ و سرور GitHub داشت؛ دو زیردامنه در این محیط پاسخ ۵۰۲ دادند. این به‌تنهایی اثبات نبود DNS نیست. آن مشاهده مربوط به سایت قبلی است، نه تأیید این نسخه. نتایج جست‌وجو را موتور جست‌وجو تعیین می‌کند؛ فارسی‌بودن متادیتا به‌معنی تضمین شکل نهایی نتیجهٔ گوگل نیست.
