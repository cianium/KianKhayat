# V10.2 — Content foundation

- Catalog supports profile, projects, certificates, curated featured items, legacy articles, skills and site translations. Records are staged/draft/archived, not public.
- Original content fields and translations remain intact, including exact dates and original HTML. Legacy articles are intentionally NOT copied into the public plaintext article table. A later migration must sanitize rich text and maintain old URL redirects without inventing dates.
- Existing featured flags and independent records are both retained; the existing project-derived feature rendering will remain authoritative on integration.
- Media bytes are content-addressed with SHA-256 deduplication, immutable source associations, size and magic-byte checks. No remote URL fetching, file serving, decoder or uploads in this phase. Do not confuse signature validation with safety.
- A single import transaction rolls back on conflicts or bad input. Repeated runs are no-ops even after edits; changed source records fail rather than overwrite. Revision history records actor and optimistic concurrency. No deletion.
- Profile captures hero names, localized biography, focus, location, social URLs, original light/dark pictures and CV; other site copy is preserved in the dictionary and original Astro source. No public portfolio changes.
- Import runs on local checkout or through a readonly mount on VPS; CI exercises actual repository fixtures and isolation. No live import performed.
- Next: polished authenticated editor, validated uploads/decoding, profile/project/certificate CRUD, then rich-text article publication and portfolio integration.
