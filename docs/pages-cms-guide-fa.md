# راهنمای سریع مدیریت پورتفولیو در Pages CMS

این راهنما مخصوص Pages CMS و مخزن `cianium/KianKhayat` است.

## افزودن یا ویرایش پروژه

۱. وارد **Pages CMS → پروژه‌ها** شو و `New entry` یا یک پروژه موجود را باز کن.

۲. قسمت‌های اصلی را **انگلیسی** وارد کن: `slug`، عنوان، شرح، فناوری‌ها، وضعیت و لینک‌های اصلی. فناوری‌ها و وضعیت برای هر سه زبان مشترک‌اند.

۳. در بخش **تصویر اصلی پروژه** تنها **یک تصویر** بارگذاری کن. تصویر کارت صفحه Home (درصورت فعال‌بودن گزینه برگزیده)، کارت Work و صفحه اختصاصی پروژه همه از همین تصویر استفاده می‌کنند. تصویر افقی 16:9 با عرض دست‌کم 1280 پیکسل، JPG/WebP/PNG و کمتر از 20MB مناسب است. از عکس‌هایی که مالک آن‌ها نیستی بدون مجوز استفاده نکن.

۴. داخل **ترجمه‌ها → فارسی و آلمانی** فقط عنوان و شرح هر زبان لازم است. مستندات ترجمه‌شده و عنوان SEO فارسی اختیاری هستند. ترجمه نام فناوری‌ها، وضعیت و URLها لازم نیست.

۵. با گزینه **نمایش در برگزیده‌های صفحه اصلی** مشخص کن که پروژه در Home هم باشد یا فقط در Work. کارت برگزیده برای پروژه‌ها خودکار تولید می‌شود؛ نیازی به افزودن همان پروژه در مجموعه «برگزیده‌ها» نیست. بخش «برگزیده‌ها» برای آیتم‌های مستقل مانند مقاله‌ها هم قابل استفاده است.

۶. دکمه **ذخیره** بالای فرم را بزن. Pages CMS تغییرات را به GitHub Commit می‌کند. آپلود عکس و ذخیره فرم ممکن است **دو Commit جداگانه** ایجاد کنند: اول فایل تصویر در `public/media/projects/` و بعد مسیر آن در `src/content/projects/<slug>.json`.

## بررسی انتشار از داخل CMS

در فهرست «پروژه‌ها» از اکشن **بررسی محتوا و ساخت سه نسخه** استفاده کن. این دکمه گردش‌کار GitHub Actions با نام `Validate and build content` را اجرا می‌کند و خطاهای محتوا، رسانه، TypeScript، لینک و Build سه‌زبانه را بررسی می‌کند.

**این دکمه Deploy مستقیم نیست.** سایت Astro به‌صورت Static در سه خروجی `dist/en`، `dist/fa` و `dist/de` ساخته می‌شود. انتشار این خروجی‌ها به تنظیمات استقرار Vercel پروژه‌های مستقل بستگی دارد. موفق‌شدن تست‌های GitHub معادل «Ready» شدن Vercel نیست.

پیوندهای بررسی:

## عیب‌یابی سریع تصاویر

- اگر **فایل تصویر در GitHub نیست**، بارگذاری در CMS کامل نشده است؛ دوباره آپلود و نتیجه ذخیره را بررسی کن.
- اگر **فایل هست ولی آدرس `thumbnail` در JSON قدیمی است**، فرم پروژه را ذخیره کن تا مسیر عکس تغییر کند.
- اگر **فایل و JSON صحیح‌اند ولی سایت عکس قبلی را نشان می‌دهد**، آخرین Production deployment همان دامنه را با GitHub Commit مقایسه کن. تا آماده‌شدن انتشار، تغییر روی دامنه قدیمی دیده نمی‌شود.
- اگر فقط **صفحه Home** عکس متفاوت دارد، مطمئن شو تغییرات قابلیت «برگزیده‌ها» منتشر شده‌اند و برای پروژه مربوطه `featured: true` فعال است.
- برای هر بار جایگزینی عکس از فایل با نام تازه استفاده کن؛ Pages CMS در این مخزن با `rename: random` نام جدید می‌سازد تا نسخه قدیمی از کش مرورگر جایگزین نشود.

## اگر پروژه جدید Build را شکست داد

نتیجه اکشن «بررسی محتوا و ساخت سه نسخه» را باز کن. گزارش `check:cms`، `check:projects` و `check:release` خطاهای قابل شناسایی را همراه نام فایل/فیلد نشان می‌دهند. مشکل را در Pages CMS رفع و دوباره ذخیره کن. بدون مشاهده خطای واقعی، حذف پروژه یا Deployهای پیاپی راه‌حل مناسبی نیست.
